# Методология и воспроизводимость

Репозиторий содержит учебные исследования, выполненные во время курса Data Science в Яндекс Практикуме. Ниже описан протокол оценки четырёх проектов с обновлённой реализацией. Остальные ноутбуки здесь не относятся к этой версии проверок.

## Постановки и протоколы

| Проект | Подход к моделированию | Оценка |
| --- | --- | --- |
| Прогноз заказов такси | Временные лаги и скользящее среднее из прошлых часов; LinearRegression, DecisionTree, XGBoost | Хронологическая выборка, TimeSeriesSplit для выбора модели, RMSE на отложенном периоде и сезонный baseline lag 24 |
| Восстановление золота | Модели регрессии для двух показателей восстановления; заполнение пропусков внутри Pipeline | TimeSeriesSplit, взвешенная sMAPE (25% rougher, 75% final), один расчёт тестовой ошибки после выбора модели |
| Токсичность комментариев | Очистка и лемматизация, TF-IDF + классификаторы | TF-IDF обучается внутри фолдов; стратифицированная CV, F1 и один финальный тест |
| Отток клиентов банка | Логистическая регрессия, дерево, случайный лес, сравнение способов обработки дисбаланса | Стратифицированный train/validation/test, статистики предобработки из train, подбор по validation и оценка на test |

Проекты включают исследовательскую подготовку данных и анализ признаков. В итоговых моделях нельзя использовать признаки, которые не были доступны на момент прогнозирования, а также подбирать гиперпараметры по результатам test.

## Запуск

Python 3.11+; команды из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-audit.txt
python -m unittest discover -s tests -v
export DATA_DIR=/absolute/path/to/datasets
jupyter lab
```

В Windows активируйте окружение подходящей командой для используемой оболочки. Ноутбуки читают данные из `DATA_DIR`; откройте их при доступном корне проекта.

Необходимые файлы: `taxi.csv`, `gold_recovery_train_new.csv`, `gold_recovery_test_new.csv`, `gold_recovery_full_new.csv`, `toxic_comments.csv`, `Churn.csv`. Наборы данных относятся к учебным заданиям Яндекс Практикума и в репозиторий не включены. Для NLP требуются ресурсы NLTK `wordnet` и `stopwords`, загрузка предусмотрена в ноутбуке.

## Проверки реализации

Синтаксис кодовых ячеек четырёх изменённых ноутбуков проверен. Шесть синтетических unit/integration-тестов покрывают:

- sMAPE, включая нулевые знаменатели и некорректные входы;
- построение временных признаков исключительно из прошлых наблюдений;
- корректное временное разбиение и заполнение пропусков внутри CV;
- обучение TF-IDF внутри фолдов, без использования словаря валидации.

Тесты пройдены при NumPy 2.3.5, pandas 2.2.3, scikit-learn 1.8.0 и SciPy 1.17.0. Диапазоны некоторых зависимостей указаны в `requirements-audit.txt`; это не полная фиксация всех транзитивных пакетов.

**Полные ноутбуки на исходных данных не запускались после изменения протоколов.** Сохранённые outputs очищены, а предыдущие численные оценки нельзя приписывать обновлённому коду. Исходные версии доступны в истории Git.

## Ограничения

- **Такси:** проверяется прогноз на один час вперёд при наличии предыдущих фактических наблюдений; он не равнозначен прогнозу всего горизонта без поступления новых данных. EDA всей истории — описательный анализ.
- **Золото:** TimeSeriesSplit предотвращает обучение на будущих строках внутри CV, но официальный test не обязательно представляет будущий временной период. Производственный временной лаг не был установлен предметно.
- **NLP:** точные дубли нормализованных текстов удалены; сходные по смыслу формулировки и зависимость между авторами не проверялись. Для исследования используется выборка не более 50 000 строк.
- **Отток:** подбор параметров многократно обращается к validation, что создаёт риск подгонки. Финальный поиск ограничен случайным лесом; дата доступности признаков не документирована.
