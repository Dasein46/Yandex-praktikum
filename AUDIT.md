# Проверка методики обучения

Проверены полностью четыре ноутбука: `prediction-taxi-orders`, `gold-recovery`, `nlp-project`, `customer-outflow`. Остальные учебные работы не считаются прошедшими полный аудит.

| Проект | Проблема | Исправление |
|---|---|---|
| Такси | Выбор семейства модели после сравнения на тесте; устаревший критерий дерева; признаки изменяли исходный DataFrame | Выбор по TimeSeriesSplit, один финальный тест, сезонный baseline lag24, неизменяемый исходный ряд, проверки временных меток и пропущенных часов |
| Золото | Оценки разных параметров накапливались в общем списке; обучение на будущих периодах внутри CV; sMAPE делил 0 на 0; merge мог менять число тестовых строк | Независимый GridSearchCV с TimeSeriesSplit, импутация внутри Pipeline, проверяемая взвешенная sMAPE, merge one-to-one с проверкой целей |
| Токсичность | Словарь и IDF обучались до CV; семейство модели выбиралось по тесту; исторические параметры подставлялись вручную | TF-IDF внутри Pipeline каждого фолда, выбор по CV, одна проверка теста, удаление нормализованных дубликатов до split |
| Отток | Медиана Tenure вычислялась по всей выборке; кодирование знало тестовые категории; старые параметры были зашиты в финальную модель | Train-only медиана и кодирование, стратификация, проверка уникальности CustomerId, финальная модель из результата валидационного поиска |

Семейства моделей сохранены. Outputs изменённых ноутбуков очищены, поскольку исправление протокола требует повторного обучения. Исторические результаты доступны в Git; они не являются метриками исправленного кода.

## Воспроизведение

Python 3.11+; из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-audit.txt
python -m unittest discover -s tests -v
export DATA_DIR=/absolute/path/to/datasets
jupyter lab
```

Открывайте ноутбук из его каталога либо запускайте ядро из корня репозитория. Файлы данных: `taxi.csv`, `gold_recovery_train_new.csv`, `gold_recovery_test_new.csv`, `gold_recovery_full_new.csv`, `toxic_comments.csv`, `Churn.csv`. Источник — учебные задания Яндекс Практикума; исходные наборы не распространяются здесь. Для NLP нужны ресурсы NLTK `wordnet` и `stopwords` (загрузка показана в ноутбуке).

## Проверки и границы результата

Выполнено 6 unit/integration-проверок: sMAPE на известных значениях и ошибочных входах; отсутствие будущих значений в признаках такси и изменения входной таблицы; отказ на нерегулярном ряде; реальное обучение линейной регрессии в временном CV с fold-local импутацией; обучение TF-IDF + логистической регрессии с проверкой отсутствия в словаре слов validation-фолда. Все прошли. Синтаксис всех кодовых ячеек четырёх изменённых ноутбуков проверен (без исполнения Jupyter magic).

Среда этих проверок: NumPy 2.3.5, pandas 2.2.3, scikit-learn 1.8.0, SciPy 1.17.0. Полные ноутбуки, XGBoost и все переборы на исходных данных не запускались: наборов данных нет. Дополнительные зависимости в requirements указаны диапазонами; это не полный lock-файл воспроизведённого эксперимента.

Ограничения:

- Такси: rolling-origin прогноз на час, а не прогноз всего горизонта без новых наблюдений. EDA всей истории сохранён как описательный; для нового эксперимента признаки следует выбирать только по train.
- Золото: TimeSeriesSplit предотвращает обучение на будущем внутри CV. Официальный test может содержать промежуточные даты; его нельзя автоматически считать будущим holdout. Неизвестный производственный лаг требует предметного выбора gap.
- NLP: удалены точные дубликаты нормализованных текстов; зависимости между авторами и близкие перефразировки не проверены. Выборка ограничена 50000 строками.
- Отток: многократное использование validation способно переобучить выбор параметров. Время доступности признаков не документировано. Сравнение способов балансировки остаётся исследовательским, финальный поиск ограничен случайным лесом.

Новых значений качества на реальных данных этот аудит не заявляет.
